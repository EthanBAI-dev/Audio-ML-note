# Markdown 数学公式规则

目标是在 GitHub MathJax、常见 KaTeX 预览器和本地 Markdown 工具之间使用稳定交集，不依赖某一个渲染器的宽容行为。

## 1. 行内公式

简单变量和短表达式使用单个美元符号：

```markdown
采样率记作 $f_{\mathrm{s}}$，频率间隔是 $f_{\mathrm{s}}/N$。
```

- `$` 必须成对，表达式不要跨行。
- 变量只出现一次、直接代入数字也能讲清时，删除变量，不要为了显得正式而引入行内公式。
- 下标是说明性标签而不是另一个变量时，用花括号和直立体写清边界，例如 `$f_{\mathrm{s}}$`，不要省略成 `$f_s$`。
- 中文句号、逗号和解释文字放在 `$` 外。
- 数学表达式不要再嵌进加粗、斜体标题或斜体图注；图注能用普通文字说清时，直接写 `k = 1`。
- 不在同一句里混用 Unicode 负号 `−` 和 LaTeX 减号 `-`。需要数学排版时写 `$-12\ \mathrm{dB}$`。

## 2. 块公式

开始和结束的 `$$` 都必须独占一行：

```markdown
$$
X[k]=\sum_{n=0}^{N-1}x[n]e^{-i2\pi kn/N}
$$
```

不要写成：

```markdown
$$X[k]=\sum_n x[n]$$
```

块公式内部只放 LaTeX 表达式，不放 `。`、`，`、`；` 等中文句读。公式是句子的一部分时，在公式前后的正文完成语法连接，不把中文标点塞进数学环境。

## 3. 单位与文字

- 拉丁单位使用 `\mathrm{}`，例如 `\mathrm{Hz}`、`\mathrm{dB}`、`\mathrm{bit/s}`。
- 中文解释移到公式外，不写 `\text{帧长（秒）}`。先在正文说明变量，再在公式中写 `T_{\mathrm{frame}}`。
- 多行公式使用 `aligned`，不要让开头 `$$` 与第一行公式、结尾 `$$` 与最后一行公式挤在一起。

## 4. 验收

对正式文章运行：

```bash
node scripts/check-markdown-math.mjs <Markdown 文件或目录>
```

检查器会报告：`$$` 没有独占一行、美元符号不成对、数学环境中的中文文字或句读。ERROR 必须清零。机器通过后仍要在最终发布平台抽查至少一篇含行内公式、多行公式、上下标和单位的文章。
