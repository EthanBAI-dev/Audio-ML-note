# 数据图规则

配图分两类，规则不同：

- **示意图**：流程、类比、分类、对比卡片。可以手绘矢量。
- **数据图**：波形、频谱、声谱图、量化阶梯、衰减曲线——任何声称"这就是某段声音长什么样"的图。

本文件管的是第二类。

---

## 1. 数据图必须来自真实计算

**不允许用色块摆出一张"看起来像声谱图"的图。**

之前的版本里，声谱图是三条蓝色矩形加一条橙色矩形。它本质是条形图：没有纹理、没有谐波间距、没有衰减。读者看完仍然不知道声谱图长什么样，也无法把正文里"横线是持续成分、竖线是一次敲击"这句话和图上的东西对应起来。**这类图不是画得不好，是它根本没有在传递知识。**

数据来源按优先级：

1. **课程自带的真实音频**（`source_course/audio_resources/`）。最有说服力，读者还能自己去听。
2. **与正文例子严格对应的合成信号**。正文说"持续嗡声 + 第 1.25 秒一下敲击"，就照这个合成，参数写进代码注释。
3. 纯示意——**只有当图讲的是概念关系而不是声音本身时才允许**（例如"采样率和位深各自换来什么"）。

真实素材还有一个附带好处：图注可以写出素材名，读者能核对。

### 跨录音比较先统一尺度

AE、RMS、ZCR 等特征图若同时比较多段录音，必须先说明是在比较**绝对电平**还是**形状与翻转密度**：

- 比较实际强弱时，不要让每段录音分别除以自身峰值；统一保留采集增益，并标明单位或参考值。
- 比较曲线形状或过零密度时，可以分别按峰值归一化，但图注必须说明绝对音量已经被删除。
- 零线阈值、静音阈值等依赖幅度的参数，必须在缩放规则确定后设置。不要拿音量相差很大的原始录音直接套同一个固定阈值，否则图可能把低电平噪声误画成“几乎不过零”。

生成脚本应把归一化、阈值和分帧参数放在同一处，使数据图和正文可以逐项核对。

### 频域图必须分开核对三件事

FFT / DFT 图不能只确认“有峰”，还要逐项核对：

1. **位置编号到 Hz 的映射**：使用与变换配套的频率轴函数（例如 `rfftfreq`），不要用 `linspace` 猜终点。
2. **双边或单边约定**：真实信号只画非负频率时，要明确普通正频率是否乘 2，以及 DC / Nyquist 是否例外。
3. **幅值归一化**：矩形窗可按样本数换算；其他窗优先按窗系数总和换算。纯音振幅、相对 dB 和功率谱密度不是同一量，图题、纵轴和图注必须说清。

教学用 FFT 生成器若只实现 radix-2，应让输入长度取 2 的整数次幂，并在代码注释中写明这是生成器限制；不要把它写成现代 FFT 库的普遍限制。图中示例数值必须在生成后人工复算一次。

### 频谱统计必须写清四项契约

质心、带宽、带能量比等统计量不能只核对公式名称，还要同时检查：

1. **权重口径**：使用幅度还是功率。两者都可能合理，但数值不同；库函数的参数 `S` 也不保证自动判断口径。
2. **频率坐标**：用与 FFT 长度和采样率配套的频率轴，不从矩阵宽高或 `linspace` 猜赫兹位置。
3. **矩阵轴方向**：先写清“频率箱 × 时间帧”或相反约定。切频带、求和与输出形状必须按这份形状契约检查，不能用 `len(row)` 猜轴。
4. **空值与近零帧**：分母可能接近零。说明稳定项、静音掩码或无效值策略，并检查它是否改变正常帧。

正文、代码和图必须使用同一份口径与轴约定；若为了比较另算一种口径，应在图题和图注中明确标出。

## 2. 连续像素场用栅格，不要用 SVG 矩形

声谱图是几万个格子的连续场。用 SVG 画意味着几万个 `<rect>`：文件几 MB、渲染卡顿，而且缩放后依然是马赛克。

正确做法是**混合**：

- 热力图本身按目标显示尺寸的约 2.2 倍渲染成 PNG，作为 `<image>` 嵌进 SVG；
- 坐标轴、标题、标注、色标图例全部是真实 `<text>`。

结果仍然是单个 `.svg` 文件：有真数据，中文在手机上不糊，体积在 30 KB 量级。

矢量能表达的东西仍然用矢量：波形用上下包络的一条 `<path>`（先按列取 min/max 再画，几万个采样点压成几百个点），频谱用 `<polyline>`，量化阶梯用折线。

## 3. 色标按声学领域惯例

| 用途 | 取值 | 理由 |
|---|---|---|
| 声谱图等热力图 | **magma** | librosa 文档与音频论文里最常见；感知均匀、明度单调、色觉障碍下仍可读 |
| 备选热力图 | viridis | matplotlib 默认，暗部略亮，弱成分更容易看见 |
| 线图、流程图、卡片 | 蓝 `#0878b9` / 暖 `#c65a3d` / 绿 `#3b8f68` | 已通过色觉障碍与对比度校验 |

**永远不要用 jet 或彩虹色标**：它的明度不单调，会凭空造出并不存在的条带。

热力图必须配一条色标图例。图例两端写**「弱 / 强」而不是 dB 数字**——零基础读者不需要读绝对值，只需要知道深浅代表什么。

动态范围（dB 下限）要调：底噪糊成一片说明范围开太大，结构断续说明开太小。白底浅色阶大约 −48 dB，深色阶大约 −55 dB。

## 4. 每张图出两个版式

同一张图必须同时有电脑版和手机版：

| | 电脑版 | 手机版 |
|---|---|---|
| 画布宽 | 880 px | 420 px |
| 排布 | 并排横排 | 竖向单列 |
| 最小字号 | 12.5 px | 13 px（360 px 正文宽度下仍约 12 px） |

**两版必须由同一份数据、同一段代码生成**，只有排布参数不同。分别手写两份，迟早会对不上。

只出手机版的代价：在宽屏上变成一条很窄的竖条，两侧大片留白，三栏对比被迫拆成上下三段，"对比"这层意思就没有了。

正文里用 `<picture>` 切换（GitHub 的 Markdown 支持）：

```html
<picture>
  <source media="(max-width: 640px)" srcset="figures/mobile/01-three-views.svg">
  <img src="figures/desktop/01-three-views.svg" alt="同一段声音的三种表示">
</picture>
```

## 5. 图注写图上看得见、正文没写的东西

最常见的浪费，是图注把正文那句话再说一遍。图注应该**引导读者去看图上的某个具体位置**。

- 差：*图 2：短窗口保住了"什么时候"，长窗口覆盖更多内容，但会把局部变化平均掉。*（正文刚说过）
- 好：*图 2：四条色条的长度差就是覆盖范围的差。最上面那条几乎看不见——一个采样点确实什么也说明不了。*

好图注常见的三种写法：

1. **指认**：「注意中间那张频谱——敲击的能量被十秒钟一平均，已经淹没在噪底里。」
2. **对应**：「左图的尖峰和右图的竖亮带，指的是同一下敲击。」
3. **交代素材**：「素材是 scale.wav，一段从低到高的音阶。右图里一级级往上的亮块就是一个个音。」
