# 审校报告模板（A 到 L）

按顺序输出，不得省略或调换。相对上一版新增 L 节（术语与可读性审计），它是发布门槛的证据。

---

## A. 文章定位摘要

主题、目标读者、读者背景、发布平台、文章目标、作者风格、可用资料。
材料没有明确说明的，写「假设：……」，不要悄悄改变定位。

## B. 评分表

按 `rubric.md` 的八个维度和权重打分。每行必须引用具体位置、说明读者影响、给出具体修改动作。
表末给出加权总分，并单独重复一遍维度 1 的分数与是否通过发布门槛。

## C. 分级问题清单

P0 / P1 / P2 / P3 分组列出。每条包含：位置、问题、为什么对目标读者是问题、修改方案。
不确定的事实标记 `需要外部核验`。

## D. 零基础读者模拟

逐段进行，按 `zero-basis-rules.md` 第 4 节的七个问题回答。
输出一张表：段落 → 新概念 → 可能不认识的词 → 需要的前置知识 → 是否存在「用陌生词解释陌生词」→ 处理方式。
明确指出读者最可能在哪一段关掉页面。

## E. 标题建议

给出三组候选：问题式、场景式、结论式，每组 2 到 3 条。
选定一条，说明理由（覆盖范围、目标读者、搜索意图）。标题本身不得含未解释术语。

## F. 深度递进大纲（仅供编辑使用）

先列出核心知识点的依赖链，再说明开头用什么现实问题，正文依次解释哪些概念，公式、代码和边界条件分别在什么内容标题下自然出现。
标出哪些术语被推迟到正文靠后位置，哪些被完全删除或移到后续文章。不要把「层」或这份内部大纲写进正式文章标题。

## G. 视觉改进方案

先审计现有配图是否仍然匹配新结构，再提出增删。
每张图给出：对应知识点、插入位置、目的、类型、必须包含的元素、禁止出现的元素、图注、alt 文本、可直接使用的生成提示词。
图注必须能被零基础读者读懂。
若发布平台包含手机端，必须写出 360 px 宽下的布局、有效字号与断行方案，并按 `mobile-figures.md` 验收。

## H. 修改计划

保留 / 删除 / 新增 / 重排 / 简化 / 举例 / 核验 / 配图，每条都要对应 C 节的某个问题编号。

## I. 完整改进版文章

完整正文，可直接发布。不含诊断批注。

## J. 修改前后对比

选取 3 到 5 处最关键的改动，原文与改写并列，并说明解决了哪个问题。
必须包含开头段的对比。

## K. 修订后评分与结论

独立重新打分，列出已解决、未解决、新引入的风险。
给出发布 / 不发布结论，并明确写出是否通过维度 1 的 8 分门槛。

## L. 术语与可读性审计

四张清单：

1. **保留的专业词**：词 → 为什么必须保留 → 首次出现时的原句（证明是「先解释后命名」）。
2. **删除的专业词**：词 → 用什么普通表达替代。
3. **后移的专业词**：词 → 移到正文靠后位置还是后续哪一课 → 理由。
4. **仍然偏难的段落**：位置 → 难在哪里 → 是否接受该风险及原因。

最后附上 `node scripts/check-readability.mjs` 的输出摘要（ERROR 数、WARN 数、未修复项的理由）。
