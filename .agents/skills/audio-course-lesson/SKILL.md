# Audio Course Lesson Writer

这套 skill 的第一任务是保住原课程的教学脉络，第二任务才是把它写成零基础、可运行、图文清楚的中文教程。不要再用统一模板重排 PPT，也不要靠写完后的关键词查重修补结构。

**职责边界：**新建课程、批量重构、素材扫描、课程脉络表和通用交接流程，先使用全局 `$build-tutorial-course`。本 skill 只补充音频课程的零基础术语、事实准确、音频实验、公式、配图和仓库约定。已有脉络表时，单篇音频课可以直接从本 skill 开始。

---

## 零、最高优先级：PPT / notebook 决定课程骨架

写一篇之前必须先读对应的 `source_course/NN - .../`：概念课直接看 PDF 的逐页演示，代码课按 Jupyter Notebook（`.ipynb`）的单元格顺序看。然后按内容匹配并扫描 `notebooklm博客/*.md`：它们是 NotebookLM 生成的补充博客稿，不是可执行 Notebook，只能补充解释、例子和检索线索，不能替代 PDF / `.ipynb` 的课程顺序。`NotebookLM课程博客_重写版/原始素材大纲.md` 也只用于检索，**不能代替直接看源文件**，因为提取文本会丢掉动画展开顺序、图与公式之间的关系。

批量改写时，先读完整组源材料并建立归属表，再改任何一篇。当前 01—10 的唯一结构依据是：

`NotebookLM课程博客_重写版/改写对照实验/PPT脉络与内容归属表.md`

执行顺序固定为：

1. 记录源文件、PPT 页序 / notebook 单元格顺序。
2. 写出这一课承接什么、首次讲什么、明确留给后课什么。
3. 把当前文章的段落标成保留、移动、删除或重写。
4. 先完成源材料的核心实验，再添加项目扩展。
5. 文章稳定后才画最终配图；内容未定稿时只画 desktop。

**不允许的做法：**先套“Why、心智模型、核心概念、FAQ、速查表”等固定栏目，再把 PPT 的知识点塞进去；只扫描术语次数，然后在文章之间移动定义；为了让一篇“自足”而完整讲掉后续课程。

**第 01 课是课程导论，不是波形、频谱与声谱图教程。** 它只建立声音分类问题、应用、课程路线、工具与学习目标。波形从 02 开始，傅里叶与频谱由 10 以后展开，声谱图的主场是 15—16。

### 来源只留在内部，不写进读者正文

PPT、PDF、Notebook 和素材大纲用于决定内部脉络与核对事实。它们可以出现在任务卡、归属表、审校报告、代码注释和交接待办中，**不得出现在文章标题、导读、正文、图内文字或图注里**。

- 不写“PPT 上说”“按照 Notebook 顺序”“第几页/第几个单元格”“原课程这样做”。
- 把这类句子改成直接讲知识或操作，例如把“PPT 给出两个理由”改成“这样做有两个理由”。
- 技术纠错直接写成“常见错误是……”并给出正确做法，不向读者展示内部来源比较过程。
- 发布前扫描 `PPT|Notebook|幻灯片|源课件|源材料|原课程`；读者正文中的命中必须清零。文件链接本身含 `source_course` 不算正文措辞。

## 一、最高优先级：读者什么都不懂

**读者对这个领域一无所知。** 不是「懂一点」，是零。

他们没学过机器学习、信号处理或计算机科学。不知道什么是分类器、模型、波形、频谱、声谱图、瞬态、相位。他们有普通高中的常识，读这篇是为了建立直觉，不是读论文。**连续撞上几个陌生词，他们就关页面了。**

下面所有规则都为这个读者服务。当准确和简单看起来冲突时，答案永远不是牺牲准确，而是**加一层**：简单的说法在前，精确的说法在后。

**发布门槛：零基础读者理解度低于 8/10 就不发，总分再高也不发。**

## 二、写法硬规矩（用户定的，优先级高于结构）

追求是**简单又明了**。做不到这一点，结构再完整也是废话。

### 1. 主语和谓语必须写出来

- ✗ 「同一段录音有三种**整理方式**」——谁在整理？「整理」通常指整理文件，和主题接不上。
- ✓ 「**电脑读**一段录音，有三种方式」——主语是电脑，谓语是读。

### 2. 动词要贴着主体，别把机器写成人

| ✗ | ✓ |
| --- | --- |
| 摆成三种样子给程序看 | 用三种方式读取 |
| 摆错了姿势，关键证据就没了 | 读取方式选错了，你要找的那个特征就已经丢掉了 |
| 三种摆法 | 三种读取方式 |

### 3. 每个数字后面必须跟一句「所以呢」

读者不会自动知道一个数字是大是小、是好是坏。**数字后面必须接一句它意味着什么。**

- ✗ 「那声敲击只让整段频谱变了 0.17%，在声谱图上却是旁边位置的 11.4 倍。」
- ✓ 「用整段频谱去读，那声敲击只让数值动了 0.17%，**小到和正常的噪声起伏分不开，程序不可能发现它响过**；换成声谱图去读，是旁边的 11.4 倍，**一眼就能指出它落在第几秒**。」

后果也要再推一步：「特征没了」——没了会怎样？「程序就永远找不到，换再厉害的程序也补不回来。」

**判据：每出现一个数字、每出现一句「就会怎样」，都自问一次「所以呢？」。答不出下一句，这句话就还没写完。**

### 4. 生活化的例子必须连回主体

举完比方要有一句把它接回来，否则读者只记住了足球，没记住录音：

> 三份材料都真实，但「第 78 分钟那个进球」只在第一份和第三份里找得到。
> **换句话说：同一场比赛，记录方式决定了你事后还能查到什么。** 电脑读录音也是这样。

### 5. 导读要帮上理解，不是复述

**判据：把导读盖住再读正文，理解成本有没有变高？** 没变高就是废话。

合格的导读给三样东西：这一课的**主语和谓语**、一个**读者认得出的现象**、**选错了会怎样**。

开头只有一行导读。**不要「读完能做到」那一行**——它和导读、小结互相复述，还占掉了开头最值钱的位置。

### 6. 标题也要有主语和谓语

术语不要顶在最前面。一个系列不要每篇都套同一个句式模子。

- ✗ 采样率与位深
- ✓ 电脑怎样把连续声音记成数字：采样率与位深

## 三、术语准入

任何专业词进正文之前，五关全过：

1. 这段话**必须**用它才讲得通吗？不是就删。
2. 能不能**先说人话，后给学名**？
3. 能不能落到一个具体场景、动作或日常现象上？
4. 解释里**有没有引入新的没解释过的词**？有就重写解释。
5. 把这个词删掉，读者还能拿到核心意思吗？能就删。

数学符号同一把尺子。只出现一次的具名变量，如果具体数字同样说得清关系，就不要引入。

引入顺序永远是：**具体场景 → 日常解释 → 专业名称 → 简单例子**。

硬约束：**绝不用没解释过的词去解释另一个词**；一段最多**一个**新的核心概念；一段扛着三个以上陌生词就必须拆开或重写。

## 四、文章结构：沿源材料自然生长，不强制十段或十三段

一篇通常只有下面几块，顺序以 PPT / notebook 为准：

1. **导读**：用一个读者认识的现象，说清本课承接上一课的哪个问题。
2. **源课程的讲解块**：按幻灯片展开顺序写。每块只讲一个新问题；“Why、心智模型、核心概念”只在源内容确实需要时使用，不是固定栏目。
3. **动手实验**：用一个说明实验目标的 `##` 大标题，不使用 `Hello World`。概念课做最小验证；实现课按 notebook 的读取、计算、画图、比较顺序走完。
4. **必要的工程提醒**：只留会改变结果的边界、单位、形状、默认值与复现参数。
5. **固定结尾**：统一使用 `## 这一课得到了什么，下一课接着讲什么`。标题固定，标题下的内容必须跟本课结果自然生长：先总结本课真正得到的答案，再明确把哪个未解决问题交给下一课；不要为了统一标题而把正文也写成重复模板。

FAQ、速查表、Before / After、对照表和“加一层”都是**可选工具**。如果它们只是再说一遍正文，就删除。不要使用“核心概念一、二、三”的统一标题把 PPT 重新分类。

**环境准备只写在 `课程总纲/README.md`。** 单篇只留一句链接。**不要写「动手做」**；文章里的动手实验与 `课程代码/lessons/lessonNN_*.py` 是同一件事。

**代码必须真跑过并留在仓库。** 正文数字必须能在对应脚本输出中找到；脚本可用 `[正文]` 和 `[脚本额外]` 区分主实验与参数扫描。公用函数放进 `课程代码/soundlab/`。先让脚本完成源实验，再把结果写进文章。

## 五、配图：哪一段该配什么

这是两套 skill 合并前**丢得最彻底的一块**。教程式结构全文只有一个词 `Diagram` 提到图，结果 01–06 试写稿新增配图数为 0，全部用 ASCII 顶替。

| 段落 | 该配什么 | 不要用 |
| --- | --- | --- |
| Before/After | 两栏对比图 | ASCII 箭头 |
| 心智模型 | 真正的流程图（方框＋箭头，标出哪一步可选） | ASCII 竖排箭头 |
| 核心概念 | **真实数据图**（真实录音算出来的） | 凭空画的示意图 |
| 动手实验 | **实测结果图**，和代码输出同源 | 只有文字 |
| 实验扩展 | 对比图，或在上一张图上加标注 | — |
| 速查表 | Markdown 表格就够 | 图 |

**ASCII 块只允许两种用途：命令行和目录树。** 其他一律画成 SVG。三条理由，都能验证：

- **手机上会横向溢出。** 360 px 屏幕大约只放得下 40 个等宽半角字符。试写稿 52 个 ASCII 块里 **19 个超过 40 列**，最宽的 83 列。
- **进不了小红书卡片。** 卡片只吃图片，ASCII 块在卡片版里等于不存在。
- **机检管不到。** `check-readability.mjs` 跳过所有 fenced code，ASCII 块里写错什么都没人发现。

**动手实验量出来的数字必须配图。** 时间和频率是连续轴，画波形、曲线或谱线；只有横轴是真正的离散类别时才使用柱状图。

真实数据要求、栅格嵌 SVG、色标约定、desktop 880 / mobile 420 / card 912 三版式、图注写法，全部见 `references/data-figures.md`。

## 六、事实准确

简单不是含糊或说错的借口。

- 分清物理量、感知判断、计算代理量、模型输出。
- 写清每个公式的适用范围和每个近似的前提。理想化结果（自由场、理想量化器、带限信号）必须就地注明。
- 算术例子和数组形状要手算或跑一遍验证。
- 分清「某个库的默认值」和「普遍定义」。
- 分清「教学简化」和「硬性技术限制」。
- 不把相关说成因果，不把任务专用的经验说成定律。
- 优先用课程原始材料、标准、官方文档和原始论文。
- 类比要标明是类比，并在必要时说清它在哪里失效。

## 七、工作流

1. 批量任务先扫描整组源材料，建立 / 更新 `PPT脉络与内容归属表.md`；单篇任务也必须读前后两课。
2. 直接查看 PDF 页序和 notebook 单元格；再用 `原始素材大纲.md` 查关键词。不能只看自动提取文本。
3. **保留原稿。** 试写和改写写到 `*对照实验/`，没有明确授权不覆盖 `零基础版_*/`。
4. 按源顺序列文章骨架，逐项标出保留、移动、删除、补台阶、实验和配图。先处理课程错位，再处理句子与术语。
5. 按 `references/zero-basis-rules.md` 做读者模拟，并用 `references/rubric.md` 记录 P0—P3 问题。
6. 先改并运行对应 `课程代码/lessons/lessonNN_*.py`，确认源实验跑通；再写正文中的代码、输出与解释。
7. 按 PPT / notebook 顺序成文。对照归属表，确认没有完整讲掉后课内容。
8. 内容未定稿只做 desktop 图；定稿后补 mobile / card。连续的时间或频率横轴不画柱状图。
9. 运行数学、可读性、概念重复和链接检查，并扫描读者正文中的 `PPT|Notebook|幻灯片|源课件|源材料|原课程`。机器检查 ERROR 0 只表示格式过关，不能证明课程顺序正确。
10. 最后重新对照源材料逐项勾选，并独立打分，列出仍未解决的风险。
