# 手机端配图规则

技术科普配图默认按手机正文宽度设计。目标不是让原本的桌面图“勉强缩小”，而是让读者在 320～360 px 宽的内容区里无需放大就能读懂。

## 版式

- 默认使用 360～420 单位宽的 SVG 画布，优先竖向单列。
- 流程、比较、分类有三个及以上项目时，上下堆叠；不要把三四张小卡横向挤在一行。
- 一张图只承担一个核心知识点。内容过多时拆成两张图，而不是缩小文字。
- 图内阅读顺序从上到下；箭头、编号和留白要让顺序不依赖桌面宽屏。
- 图注放在 Markdown 正文中，图内只保留理解机制必需的文字。

## 窄屏重排不能删掉知识图形

- 手机端改版的目标是重排图形，不是把原图简化成纯文字卡片。凡是承担机制说明的曲线、箭头、位置关系、变化过程和前后对比，都应保留。
- 空间不足时，优先增加画布高度、把横向关系改成纵向关系、让说明文字换行或拆成多张图。不要为了维持固定高度而删掉有解释作用的文字或图案；只有确认内容重复时才精简。
- 卡片中尽量保留一个与知识点直接对应的小图形，例如传播用扩散箭头、采样用波形和采样点、时间尺度用时钟。只有装饰作用的通用图标不能代替机制图。
- 图案可以变简，但读者仍应能从形状看出本卡片在讲什么；如果遮住文字后图案便没有意义，就需要重新设计。
- 让知识图形成为视觉主体。卡片左右分区时检查中间是否存在无效空白；如果有，应扩大图形区，而不是把示意图困在小方框里。
- 避免连续使用圆角胶囊、状态气泡和重复卡片来包装每一句话，这类组件容易产生模板化观感。优先采用大图、直接标注、细分隔线、坐标和空间关系。
- 检查文字与图形的视觉重量：说明文字不应比承载知识的曲线、结构或对比图更醒目。
- 验收时除检查字号和裁切外，还要与宽屏原图对照：确认没有丢失会影响理解的视觉信息。

## 字号与文字

以图片缩放到 360 px 宽为验收基准：

有效字号 = SVG 字号 × min(1, 360 / viewBox 宽度)

- 正文标签有效字号不得小于 12 px；次要刻度不得小于 11.5 px。
- 单行中文尽量不超过 18 个字；超过时主动断成两行。
- 不使用大段说明文字、密集图例或横排表格。
- 一两句帮助读者理解图形的说明应完整保留，并通过换行、增加卡片高度和留白来容纳。
- 直接在曲线、箭头或卡片旁标注含义，减少读者在图例和图形之间来回寻找。
- 桌面横表在手机端不要原样压缩。按“每一行变成一张纵向卡片”做语义转置：行标题放在卡片顶部，各列名变成彩色短标签，单元格说明完整保留。手机与桌面内容必须一一对应。

## 图表与比较

- 坐标轴只保留解释结论所需的刻度，避免完整复刻论文图。
- 比较项使用相同尺度和明确标签；不能只靠颜色区分。
- 颜色承担强调作用，文字、形状或线型仍要能独立说明差异。
- 公式不塞进图片，除非公式本身就是图的知识点；通常放回 Markdown 正文。

## 系列文章的课程位置图

连续课程可以在标题导读之后放一张紧凑的位置图，帮助读者确认“这是第几课、属于哪一组、前后还有多少内容”。它属于导航信息，不是文章内部的“基础层 / 进阶层”脚手架。

- 只显示课程总数、当前课、阶段分组和当前阶段；不要重复整篇总纲。
- 不使用“初级、进阶、专业层”等标签，也不告诉读者正文应该读到哪一层。
- 电脑版可以横向展示完整课程节点；手机版改为五阶段概览加当前组内进度，避免横向挤入二十多个小字标签。
- 当前课不能只靠颜色表示，还要同时写明课号、课程标题和组内位置。
- 图片应比正文知识图更矮、更轻，不使用大段解释、重复气泡或装饰图标。
- 同一系列全部位置图由一份课程清单生成；新增、删除或改名课程时统一更新，防止各篇进度不一致。

## 验收

1. 把 SVG 按 360 px 宽渲染，而不是放大到桌面尺寸检查。
2. 逐张确认标题、标签、刻度和注释无需放大即可阅读。
3. 检查文字是否裁切、重叠，箭头是否指向明确，阅读顺序是否从上到下。
4. 与原图对照，检查机制、关系、趋势等视觉信息是否在窄屏版中仍然存在。
5. 运行 node scripts/check-svg-mobile.mjs <图片目录>，清零 ERROR，并人工复核 WARN。
6. 最后核对 Markdown 的 alt 文本和图注是否仍与新图一致。
