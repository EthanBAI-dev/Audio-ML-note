## B 教程式改了什么

不再先摆固定栏目，而是先读完本课的主线材料，记录原始顺序、概念归属和与相邻课程的交接，再围绕一个可运行实验成文。每篇的小标题跟着内容走；统一的只有开头导读、课程位置、代码入口，以及结尾的「这一课得到了什么，下一课接着讲什么」。

三条最明显的变化：

1. **每个正文结论都有实测输出**，不是示意。数字全部在 Python 3.12.10 / numpy 2.5.2 / librosa 1.0.0 上真跑出来的。
2. **每课只拥有自己的新概念。** 需要前置知识就回链，需要后续实现就留悬念，不在相邻文章里重新讲一遍。
3. **文章只放讲清实验所需的代码。** 参数扫描、边界检查和完整输出保留在 `课程代码/`，环境准备只放课程总纲。

## 试写时新挖出来的可验证事实

这些是原稿里没有、写教程式版时实测出来的：

- **01**：那声敲击只让整段频谱变了 **0.17%**，在声谱图上却是相邻列的 **11.4 倍**。「证据被抹掉」第一次有了数字。
- **03**：RMS 精确相同的正弦和白噪声，质心 229 Hz vs 3997 Hz，**LUFS 差 3.6**。
- **04**：3 Hz、7 Hz、13 Hz 在 fs=10 下的采样值逐个列出来——3 和 13 完全相同，7 是它的相反数。「无法区分」不再是形容词。
- **05**：把六段能量倒序，均值和标准差**一位小数都不差**。
- **06**：同一帧加 Hann 窗后 RMS 从 0.05299 掉到 0.03413，掉了三分之一。

## 已知的取舍

- 长度增加 20%–30%（第 06 课因为原稿本来就短，涨了 3.3 倍）。更像文档，适合边看边敲，不适合一口气读完。
- 原 skill 的 §6（API Key、`.env`）和 §10（Async、Security、Deployment）是给软件教程设计的，DSP 课用不上，已在 skill 末尾注明按实际情况裁掉。
- **和零基础规则有一处真冲突**：skill 要求「开头 200 字内说清是什么」，而零基础规则要求「前两段不出现未解释术语」。01 和 03 的「这是什么」一节因此各留了一个 WARN（一段里引入 3 个和 6 个术语）。处理办法是每个术语当场加粗并配一句话解释，ERROR 已清零。
- **第 10 课那种纯建立直觉的课要小心**：这套 skill 要求「最小可运行 Demo + 完整输出」，可能会逼出并不必要的代码。
